# tpt-search Design Specification

## Mission

Build a complete, distributed, hybrid search and analytics engine in pure Rust that provides:
- **Unified Hybrid Search**: Scalar (inverted index), vector (HNSW), and graph (property graph) queries in a single engine
- **Edge-to-Cloud Native**: CRDT-based synchronization for offline-first deployments (police field units, healthcare clinics, aviation maintenance)
- **Formally Verified Query Execution**: SQL-like query planner with `tpt-telos` guarantees against injection, panics, and resource exhaustion
- **Time-Series Aware**: Native support for temporal data, multi-rate streams, and range queries over time
- **Zero Apache-2.0 Dependencies**: Every component is strictly MIT or 0BSD licensed, replacing Elasticsearch/OpenSearch/Solr

This is not a Tantivy wrapper. This is a ground-up reimplementation that replaces the JVM-based Elasticsearch monopoly with a memory-safe, formally verified, distributed alternative designed for the TPT verticals.

---

## The Problem We're Solving

### The Elasticsearch/OpenSearch Licensing Trap
- **Elasticsearch**: Was Apache-2.0, then Elastic changed to SSPL (not open-source by OSI definition) in 2021.
- **OpenSearch**: AWS forked it back to Apache-2.0, but it is a JVM-based monolith with massive operational overhead.
- **Apache Solr**: Apache-2.0, JVM-based, legacy architecture.
- **Algolia / Pinecone**: Proprietary SaaS, expensive, vendor lock-in.

**The Cost**: Enterprises pay $50k–$500k/year for hosted Elasticsearch, or operate heavy JVM clusters that consume 10× the RAM of equivalent Rust workloads.

### The Fragmentation Problem
Modern applications need three types of search, but they are split across three different databases:
1. **Scalar search** (text, numbers, dates) → Elasticsearch / PostgreSQL
2. **Vector search** (embeddings, similarity) → Pinecone / Qdrant / Milvus
3. **Graph search** (relationships, traversal) → Neo4j / ArangoDB

This means:
- Three separate systems to operate, monitor, and secure
- Three separate consistency models
- Three separate backup/restore procedures
- Expensive ETL pipelines to keep them in sync

### The Edge-to-Cloud Gap
For TPT's verticals:
- **Police**: Field units need offline search capability, syncing to central records when connectivity returns
- **Healthcare**: Rural clinics need local patient record search, syncing to central EHR
- **Aviation**: Maintenance crews in remote locations need offline technical manual search
- **Robotics**: Edge devices need local sensor search, aggregating to cloud analytics

No existing search engine handles this gracefully. Elasticsearch assumes always-on cloud infrastructure.

    #[cfg(target_arch = "x86_64")]

            return unsafe { cosine_similarity_avx2(a, b) };
        }

    {
        if std::arch::is_aarch64_feature_detected!("neon") {
            return unsafe { cosine_similarity_neon(a, b) };
        }
    }
    cosine_similarity_fallback(a, b)
}

// Formal contracts for query execution
#[requires(query.is_well_formed())]
#[ensures(result.is_ok() ==> result.documents.len() <= query.limit.unwrap_or(usize::MAX))]
#[ensures(result.is_ok() ==> result.documents.iter().all(|d| schema.matches(d)))]
pub fn execute(executor: &QueryExecutor, plan: &QueryPlan) -> Result<QueryResult, QueryError>;

// Resource bounds
#[requires(plan.estimated_cost < MAX_QUERY_COST)]
#[ensures(result.is_ok() ==> result.took_ms < MAX_QUERY_TIME_MS)]
pub fn execute_with_bounds(executor: &QueryExecutor, plan: &QueryPlan) -> Result<QueryResult, QueryError>;

// Injection prevention
#[requires(!query.contains_sql_injection_patterns())]
#[ensures(result.is_ok() ==> !result.contains_unexpected_data())]
pub fn execute_safe(executor: &QueryExecutor, query: &Query) -> Result<QueryResult, QueryError>;

impl LwwDocument {
    pub fn merge(&self, other: &LwwDocument) -> LwwDocument {
        if self.timestamp > other.timestamp {
            self.clone()
        } else {
            other.clone()
        }
    }
}

        Router::new()
            .route("/api/v1/search", post(self.search))
            .route("/api/v1/index/:name", post(self.create_index))
            .route("/api/v1/index/:name/doc", post(self.index_document))
            .route("/api/v1/index/:name/doc/:id", get(self.get_document))
            .route("/api/v1/index/:name/doc/:id", delete(self.delete_document))
            .route("/api/v1/graphql", post(self.graphql))
            .route("/api/v1/stream", get(self.stream_results))
    }

    async fn search(&self, request: SearchRequest) -> impl IntoResponse {
        let query = parse_query(&request.query)?;
        let result = self.executor.execute(&query)?;
        Json(result)
    }
}
